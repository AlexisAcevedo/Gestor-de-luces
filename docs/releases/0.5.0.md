## Highlights in v0.5.0

- **Internal rebrand to `WizConsole` (`wiz_console`) with transparent `v0.4.3` migration.** Renamed the Python package and CLI distribution to `wiz_console` / `wiz-console`, updated desktop identity (`AppUserModelID = AlexisAcevedo.WizConsole`, single-instance Win32 primitives `Local\WizConsole.*`, named threads `WizConsole*`, rotating log `wiz_console.log`), and updated packaging (`packaging/wiz_console.spec`, `WizConsole-Setup-0.5.0.exe`, `WizConsole-portable-0.5.0.zip`) while preserving the Inno Setup `AppId` for seamless in-place upgrades. On first launch, existing user data (`%LOCALAPPDATA%\GestorDeLuces` / `~/.gestor_de_luces`), `HKCU\...\Run\GestorDeLuces` autostart entries, and WebView2 `localStorage` preferences migrate idempotently without deleting legacy backups.
- **Fixture deletion with Undo & MAC-based DHCP reconciliation.** Added end-to-end `remove_bulb` across the inventory service, facade, IPC allowlist, and UI drawer (with explicit target cleanup, an unnested delete button outside the checkbox `<label>`, and a 5-second **Undo** toast that pauses on focus and flushes on `beforeunload`). Updated `discover_bulbs()` to match moved fixtures by normalized MAC address (`a8:bb:50:...` / `a8bb50...`), preserving friendly bulb names and `selected_ips` across router DHCP lease changes.
- **Session state persistence, tray stream toggles & Ambilight floor alignment.** Persisted `selected_ips`, `auto_sync`, `favorite_builtin_scenes`, `ambilight_prefs`, and `music_prefs` inside `settings.json`, migrating existing browser `localStorage` built-in favorites once on upgrade. Added checkable `Ambilight` and `Music Sync` toggles directly in the system tray menu (`toggle_ambilight` / `toggle_music_sync` using saved defaults), and aligned `min_brightness` to a strict `10–20%` range across backend and UI while fixing Ambilight mode documentation (`vibrant` / `average`).
- **Opt-in system-wide Windows global hotkeys.** Added the `GlobalHotkeyManager` port and Win32 `RegisterHotKey` adapter (`WindowsGlobalHotkeyManager` on dedicated message-pump thread `WizConsoleHotkeys` using `MOD_NOREPEAT`). Disabled by default; once enabled in **Keyboard shortcuts (?)**, shortcuts work even while minimized to the tray (`Ctrl+Alt+P/Up/Down/A/M/W` defaults), report Win32 conflicts (`in_use`) inline, and leave zero orphan threads on exit.

## Breaking changes

- Internal Python package and CLI entrypoint renamed from `gestor_luces` / `gestor-luces` to `wiz_console` / `wiz-console`, and runtime user data moved from `%LOCALAPPDATA%\GestorDeLuces` to `%LOCALAPPDATA%\WizConsole`. Upgrading from `v0.4.3` migrates data, autostart, and UI preferences automatically on first run.

## Tests and CI

- 383 Python tests and 168 JavaScript tests (`node --test`, zero npm dependencies, 88.46 % line coverage across all 9 `ui/js/` modules), including `tests/test_upgrade_0_5_0.py` simulating a `v0.4.3` -> `v0.5.0` upgrade.
- CI on Windows runs Python 3.12 and 3.14 plus `js tests`: `ruff check`, blocking `bandit` and `pip-audit`, and per-package coverage gates (`domain >= 90%`, `application >= 75%`, `adapters >= 55%`).

## Known limitations

- One lost `getPilot` reply marks that bulb offline, so if every target drops the read at the same moment the tray offers "Turn on" while the bulb is already on. Label and action stay consistent, and it self-heals on the next poll.
- Global Windows hotkeys rely on Win32 `RegisterHotKey` and therefore do not intercept shortcuts swallowed by elevated apps or exclusive fullscreen games; non-Windows hosts report global hotkeys as unavailable cleanly.
- The About box is a native message box without an owner window, so it appears as its own alt+tab entry while it is open.
