## Highlights in v0.4.2

- **No more light-theme flash on dark startup.** Launching the app with *Atmospheric Dark* saved in `settings.json` rendered the light layout first until `ui/js/app.js` finished `DOMContentLoaded` and the initial IPC round-trip (`get_initial_state`), while empty `localStorage` under fresh WebView2 origins also reset to `DEFAULT_THEME`. `DesktopApplication.create_window()` now passes `#theme=<theme>` on the initial window URL, and `ui/js/theme-boot.js` runs synchronously in `<head>` before `themes.css` (preserving the strict `script-src 'self' file:` CSP) to apply `data-theme` and `<meta name="color-scheme">` prior to first paint.
- **Fresh UI assets on every launch and upgrade.** `pywebview`'s built-in `BottleServer` set `Cache-Control` on the global `bottle.response` before calling `bottle.static_file()`, which returns a new `HTTPResponse` and discarded those headers, leaving WebView2 free to serve stale cached JS/CSS files on `127.0.0.1:42001`. `NoCacheBottleServer` now attaches `Cache-Control: no-store, no-cache, must-revalidate`, `Pragma: no-cache`, `Expires: 0` (plus `Clear-Site-Data: "cache"` on HTML) directly to `static_file()`, paired with a per-launch `?v=<token>` query.
- **Clearer Light/Dark theme labels and fully localized About dialog.** Renamed the visible theme switcher labels and tooltips from *Stone* / *Piedra* to `Light` / `Dark` (English) and `Claro` / `Oscuro` (Spanish) while preserving the internal `architectural-stone` and `atmospheric-dark` identifiers, and localized both the native About dialog title (`About` / `Acerca de`) and the Spanish application display name.
- **Unmistakable ON/OFF contrast in the Light theme.** Replaced the pale cream OFF bulb aperture with the dark smoked-glass `--aperture-off-bg` lens against a glowing haloed ON orb (even for 5000 K–6500 K daylight whites), and updated Light-theme power buttons to a recessed stone OFF state versus a Braun signal vermilion ON state (≥ 5.0:1 WCAG AA contrast).
- **Reliable bridge startup and automated CI release pipeline.** Signals `WebviewBridge` readiness only once the background `asyncio` event loop is actually running (fixing the startup race on loaded runners), writes `SHA256SUMS.txt` with LF and no BOM, and builds, verifies, and publishes Windows releases from CI.

## Known limitations

- One lost `getPilot` reply marks that bulb offline, so if every target drops the read at the same moment the tray offers "Turn on" while the bulb is already on. Label and action stay consistent, and it self-heals on the next poll.
- A live read can still overwrite a fresher optimistic write made in flight by another consumer for one cycle (the same class of race the web UI already had).
- Because the JavaScript-facing refresh notifies the UI and that schedules a tray refresh, the effective live tray refresh is about 10 s with the 5 s default poll.
- The About box is a native message box without an owner window, so it appears as its own alt+tab entry while it is open.
