## Highlights in v0.4.1

- **Help › About finally shows real data.** The dialog was built from the display name, the version and a licence that was never passed, so it always rendered the placeholder label and had no author or repository at all. It now reports the version, the licence (MIT), the author and the repository the project already declares, read from module constants so a frozen build shows the same thing it shows from source.
- **No more ghost entry in alt+tab.** The WinForms form that pumps the tray messages stays visible for the whole session (transparent, minimised, zero-sized, titled `gestor_luces`), and `ShowInTaskbar = False` only removes the taskbar button. It now carries `WS_EX_TOOLWINDOW` before the message pump shows it, so the switcher stops listing it as a leftover. Measured with a live `EnumWindows` probe: ex-style `0x90000` → `0x90080`, zero alt+tab candidates left from the process.
- **Tray on/off acts on the bulb's real state.** The entry baked its direction when the menu was built (`turn off if on`), out of a cached snapshot that only the hidden WebView ever refreshed — with the app in the tray that staleness window was unbounded, so the item could offer and apply the opposite of the real state. It now dispatches a state-free toggle that re-reads the target bulbs over UDP and applies the inverse, and the label, tooltip and icon colour are refreshed from the bulbs on the periodic poll.
- **Quitting from the tray exits cleanly.** Clicking *Salir* could pop a `.NET Framework` dialog — *"Colección modificada"* — and leave the process alive. The tray poll was reusing the JavaScript-facing refresh, whose success envelope notifies the view, so every poll requested a native menu sync; during `window.destroy()` that met a `menu_sync` walk over `native_form.Controls` with a live .NET enumerator, and the resulting `InvalidOperationException` escaped into the message loop where the modal CLR dialog blocked shutdown. Fixed at three levels: a non-notifying `refresh_tray_states` for the poll, a materialised `Controls` walk, and a late `apply()` ignored once the tray view is stopped.
- **The taskbar button shows the app icon.** The button's identity and icon come from the process AppUserModelID, not from the window icon: without one, running from source grouped the window under `python.exe` and showed the Python logo even though the form already had the shipped `.ico`. The process now has its own identity before the first window exists and the window receives the `.ico` with `WM_SETICON` in both icon sizes.
- **One product name everywhere.** The installer declared `WiZ Lighting Console` while the executable metadata, the About dialog and the window title say `WiZ Architectural Lighting Console`, so the *Apps & features* entry and the Start Menu group named a product that existed nowhere else. The installer now uses the same string, keeps its `AppId` (upgrades still replace the previous install) and no longer carries a stale `0.3.1` version fallback.

## Breaking changes

None. No public API, CLI flag or configuration format changed.

## Tests and CI

- 216 Python tests and 102 JavaScript tests (`node --test`, zero npm dependencies).
- CI on Windows: Python 3.12 and 3.14 plus a dedicated JS job; `ruff check` and `ruff format --check`; coverage gated **per package** (domain 90 %, application 75 %, adapters 55 %), all above their floors.
- New regression coverage: the About body, the tool-window style and its degradation paths, the two degradation cases of the window icon and the AppUserModelID, the state-free power toggle end-to-end against the UDP simulator, the non-notifying tray refresh, and the poll cadence surviving a failed live read.

## Known limitations

- One lost `getPilot` reply marks that bulb offline, so if every target drops the read at the same moment the tray offers "Turn on" while the bulb is already on. Label and action stay consistent, and it self-heals on the next poll.
- A live read can still overwrite a fresher optimistic write made in flight by another consumer for one cycle (the same class of race the web UI already had).
- Because the JavaScript-facing refresh notifies the UI and that schedules a tray refresh, the effective live tray refresh is about 10 s with the 5 s default poll.
- The About box is a native message box without an owner window, so it appears as its own alt+tab entry while it is open.
